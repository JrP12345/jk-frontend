## Scope and confidence

Reviewed frontend checkout, navigation, local storage, offline shell, purchase entry, customer history, public catalogue and printing; backend sales/quote/FEFO services, purchase contracts, reports, prescription authority, tax validation, transaction handling and relevant model indexes/test cases. Consulted official vendor and government sources below.

**Verified means present in code**, with existing regression coverage where noted. This audit did not query the selected application database, apply indexes, exercise real customer data, measure live API latency, rerun the test suites or test physical printers. Database findings concern schemas/query design, not the health of deployed records. Previous browser previews used synthetic APIs; they do not establish actual Save performance or real-store usability.

## Biggest engineering and workflow findings

1. **Save needs profiling, not another endpoint rewrite.** `PharmacySaleQuoteService.prepareCounterSale` batches medicine lookup, then sequentially reads and validates every historical lot per medicine, capped at 5,001. `PharmacyInventoryService.dispenseMedicineFEFO` subsequently rereads the medicine, eligible lots and tax evidence before writing. This is repeated preparation on the critical path. It is a credible latency contributor, not a measured root cause. Preserve reconciliation, FEFO, concurrent-stock protection and required audits when optimizing.
2. **Readiness is in the hot path.** Each new sale checks for an operation receipt and calls `requirePharmacyDispenseIndexes`, which lists source indexes. Consider startup/deployment readiness and carefully scoped reuse of validated readiness, rather than repeated metadata queries. Never replace real unique indexes with a client-side duplicate check or silently auto-create them during billing.
3. **Shared writes can create contention.** Issuer, branch, invoice number and drawer claims protect real financial boundaries. Measure conflicts/retries across multiple tills before changing them; removing locks for speed can permit stale authority or inaccurate cash.
4. **Search limitations become a billing bottleneck.** Server search uses case-insensitive regex over name/generic while sorting by ID. Current medicine indexes do not establish efficient normalized name/generic token search. Verify query plans before adding indexes. Local cache misses correctly fall back online, but cannot offer complete offline discovery.
5. **Inward entry is the strongest missing time saver.** Free quantities and tax/cost logic already exist. Missing distributor item-code mapping and purchase-file import force repeated manual entry. Reuse purchase draft validation/posting/receipt commands; never import directly into stock and skip the supplier document.
6. **Stock alerts stop short of replenishment.** There are reorder thresholds and low/expiry reports, but no dedicated shortbook, supplier order preparation or rack/shelf field in the reviewed medicine model. Start with a small persistent shortage list and supplier-linked purchase draft, not a procurement marketplace.
7. **UI problems need state-based acceptance.** Horizontal category scrolling/fades, compact quantities, stable normal Save footer, shared compact navigation and removal of the counter statistics row already have implementations. Do not label those historical screenshot defects as currently reproduced. Check cold restore, capability errors, changed price, unknown price, noncollector, credit, pending outcome, return to counter and short/mobile viewports. Keep totals/actions visible and use one intended scroll region per panel.
8. **Compliance readiness is more than UI fields.** Issuer stores licence numbers/review evidence; qualified professionals have reviewed validity/revocation checks. That does not prove the premises licence remains valid or records/backups meet actual inspection/retention requirements. Avoid a misleading “fully compliant” badge and never infer drug schedules or current GST from fuzzy product names/defaults.
9. **Maintainability is a secondary risk.** Checkout contains cart, payment, recovery, local persistence and navigation state; several issue paths intentionally serve different clinical/financial authorities. Extract only shared presentation/state helpers needed for a proven fix. Consolidate dated operational documentation; do not merge authorities merely to reduce file count.

## Indian requirements: supported controls versus unresolved acceptance

- Prescription supply must preserve the applicable prescription/professional evidence. Schedule H1 supply has a separate register and three-year record requirement. Existing H/H1 capture is relevant; verify actual inspection export, retention, backups and pharmacist practice before activation. [CDSCO Rule 65/97 amendment](https://cdsco.gov.in/opencms/resources/UploadCDSCOWeb/2022/drug_rules/DR_G.S.R.%20588%28E%29%20dt_30.08.2013_Amendment%20Rule%2065%2C%20Rule%2097_Inclusion%20of%20Sch%20H1%2C%20Labelling%20requirements%2C%20Sch%20H%20list.pdf), [Drugs Rules](https://cdsco.gov.in/opencms/resources/UploadCDSCOWeb/2022/drug_rules/Drugs%20Rules%2C%201945.pdf).
- Tax invoices need applicable issuer/recipient, serial/date, goods/quantity, classification and tax particulars; a PDF is not proof of IRP reporting. Preserve the current block on unsupported electronic-reporting issuers/B2B, and validate applicability with the actual business profile. [CBIC rules compilation, Chapter VI](https://cbic-gst.gov.in/pdf/amended-01012022-CGST-Rules-2017-Part-A.pdf), [GSTN e-invoice overview](https://tutorial.gst.gov.in/downloads/news/e_invoice_overview.pdf).
- Current schedule classification, tax treatment and price-control applicability require maintained reviewed source data. A price at/below captured MRP alone does not establish every applicable price-control obligation. No blanket medicine GST rate or automatic legal substitution is proposed.
- Check later final amendments and state-specific conditions for the pilot. The [current CDSCO Gazette list](https://www.cdsco.gov.in/opencms/opencms/en/Notifications/Gazette-Notifications) distinguishes draft proposals from enacted changes; this audit does not claim an exhaustive legal review through November 2026.
