# Ekavyu architecture, dependencies and technical debt — 17 November 2026

## Assessment and coverage

Keep the modular monolith, MongoDB, Redis coordination and existing durable outboxes. The application already has useful domain services, transactional financial/inventory operations, tenant-aware authorization, recovery commands and separate worker executables. Microservices, a message broker, Kubernetes, a new ORM or a database replacement are not justified by the evidence collected here.

This is a repository-wide inventory with deeper inspection of security, data access, integrations and deployment boundaries, plus focused remediation. It is **not** a line-by-line proof of every business rule, a penetration test, a complete publisher/supply-chain investigation or production certification. No code was removed merely because a static scanner found no imports. Existing uncommitted pharmacy work was preserved.

Scope: frontend source/routes/components/hooks/stores/services/offline code and build configurations; backend routes/controllers/services/models/schemas/middleware/platform utilities, jobs/workers/providers/deployment and scripts; both complete npm lockfiles; and the standalone HTML/CSS/inline-JS landing site. Generated outputs, dependency directories, backups, credentials and environment values are excluded from source analysis. The connected MongoDB check below reads only collection/index metadata.

Evidence inventories:

- Frontend checkpoint: 735 JS/TS source files, including 224 test files, 39 direct package declarations and 788 lockfile package locations; 19 generated offline sources excluded from the graph.
- Backend checkpoint: 916 source files, including 268 test files, 31 remaining direct package declarations and 427 lockfile package locations. These include controllers, services, scripts and tests, not 916 independently deployed modules.
- Landing-site checkpoint: static HTML/CSS/inline JS, assets and README; no npm manifest or package graph.
- Each dependency record includes exact locked version, recorded licence, dependency/peer edges and direct source/configuration references. These are install locations, **not unique package totals**. Metadata licences do not replace review of bundled/native notices.

The inventory uses literal-import heuristics. Type-only edges are excluded from runtime-cycle candidates. Imports inside fixture source strings, dynamic discovery and generated Next declarations can produce unresolved candidates; those are not proven broken imports. Package scripts, framework entry points, peers and build tools are reviewed separately. The bulky generated snapshots were removed during the 18 November cleanup; the findings and checkpoint counts above remain historical evidence. Reproduce from the frontend with `node ../backend/scripts/architecture-inventory.mjs . build/architecture-inventory.json`, or use the corresponding backend/landing root. Build output is ignored in each repository.

## Boundaries, data access and scalability

| Area | Assessment and remaining work |
| --- | --- |
| Authentication / tenant isolation | Session-derived authority, organization/location checks and dedicated clinical/patient ownership helpers are valuable. Model plugins are not blanket isolation: they do not scope all aggregates and deliberately permit some internal/root contexts. The advisory scanner emitted **142 candidates**, not 142 proven vulnerabilities. Representative actual tenant-route and repository tests passed; remaining candidates require caller/data-flow review. |
| Booking, queue and clinical records | Existing transactional/domain-service checks should be preserved. Large queue/appointment/onboarding/clinical controllers concentrate state transitions and authorization. Extract coherent responsibilities only with their direct tests; a cosmetic wholesale rewrite would increase risk. |
| Financial / pharmacy correctness | Preserve source invoices, exact product/pack identity, confirmed stock receiving, idempotency receipts, offline owner rules and explicit ambiguous-outcome reconciliation. Similar-looking billing, refunds, purchase receiving and versioned offline calculations are not interchangeable implementations. |
| MongoDB queries / indexes | Existing scoped/keyset queries, bounded read windows and index-preparation service are preferable to speculative new indexes. Actual schema/index metadata matched. Representative cardinality/execution plans and production p95/p99 were not measured here; old October synthetic measurements are not current capacity evidence. |
| Workers / notifications | Existing leased MongoDB outboxes, bounded retries, backpressure and four worker processes are sufficient. Monitor each worker's readiness/progress/queue age separately. SMTP acceptance, API readiness and webhook receipt do not prove final delivery. |
| Frontend state / caching | Zustand owns session/workspace state, React Query serves selected server-state screens, and local request hooks handle other bounded forms. This is inconsistent but not proof of duplication. Do not introduce another cache or bulk-convert sensitive recovery flows. Preserve logout/organization-scoped cleanup and the existing encrypted offline journal. |
| Files / privacy | R2/S3 abstraction and short-lived authorization-checked URLs reduce coupling. Byte/type validation is not antivirus certification. Real bucket policy, malware/quarantine policy, retention, scanning and off-site recovery remain operational acceptance. |
| Build / infrastructure | Node/Docker Next and experimental Cloudflare share application source. Keep both because both are intentional existing targets, but require separate acceptance. Native build, Cloudflare build and transport passing do not erase the missing-profile status failure. Docker image tags still need release digest/version pinning and container scanning. |
| API consistency | Most handlers use shared response/error helpers, but webhook/protocol endpoints intentionally have provider-specific envelopes. Validation is mixed between schemas and domain parsers. Consolidate ordinary application contracts incrementally; do not rewrite required provider/webhook response formats. |
| Logging / monitoring / recovery | Existing redaction, request correlation, histograms and operator backup/restore tools are useful. Deployed alerts, restores/decryption, key custody, RPO/RTO and failover have not been proven by this repository audit. |

## Dependencies, providers and open-source choices

All 70 direct declarations and 1,215 locked installation locations are covered by the inventories; source use and licences are available per record. Current advisory databases were queried for both whole lockfiles. Individual transitive maintainer identity, every upstream release history and every bundled licence text were **not** independently audited; absence of an npm advisory is not a safety guarantee.

| Dependency / integration | Decision and licence / maintenance considerations |
| --- | --- |
| React, Next, Fastify, Mongoose, Zustand, React Query, Axios, Fastify plugins | Retain the current maintained stack. Most are MIT. Axios already centralizes credential/refresh/recovery behavior; replacing it with raw fetch would move maintenance into app code without demonstrated benefit. Inspect current pinned licence metadata in the inventory rather than relying on this group label. |
| Tailwind/PostCSS, Vite/vinext/Cloudflare, TypeScript and test/build tools | Required configuration, CLI or peer usage explains absence of runtime imports. Do not delete React-RSC/Vite plugins, types or PostCSS tooling based on an import count. Cloudflare tooling is prerelease and creates a separate compatibility burden. Latest cf candidates require newer Node 24 minors than this PC; targeted same-major dependency patches preserve the current tool contract. |
| Custom private `fast-glob` adapter | It is selected by a root override and consumed by Next lint and Vite discovery. Retain it with its 5 consumer/contract checks. It is owned private code, not an unidentified third-party permissive licence. Prefer a supported upstream version when its compatibility/security contract is demonstrated. |
| Speakeasy | Actual runtime MFA dependency, MIT, explicitly [unmaintained upstream](https://github.com/speakeasyjs/speakeasy). [OTPAuth](https://github.com/hectorm/otpauth) is MIT and has [current release activity](https://github.com/hectorm/otpauth/releases); evaluate replacement through RFC vectors, existing secrets, QR labels, padding, drift/replay and recovery tests. Not silently replaced during this cross-application audit. The fixed-code bypass is removed now. |
| Redis / ioredis | Keep coordination and pub/sub. The client is MIT; the server's [licence depends on version](https://redis.io/legal/licenses/), so `redis:7-alpine` is not an adequate licence/version assertion. [Valkey](https://github.com/valkey-io/valkey) is a maintained BSD-3-Clause alternative worth validating for existing leases, Lua, sessions and pub/sub before deployment; not automatically substituted. |
| MongoDB | Retain per request and because transactions/index semantics are integral. Mongoose's MIT licence does not make the [MongoDB server SSPL](https://www.mongodb.com/legal/licensing/server-side-public-license) permissive. Do not promise a database switch as a free cleanup. |
| S3/R2 / AWS SDK | Existing Apache-2.0 client and S3-compatible boundary; storage/provider terms and costs are separate. MinIO or another S3-compatible service would add hosting/backup/security and its own licensing obligations. No cost evidence justifies replacing R2. |
| SMTP / Nodemailer | Retain provider-neutral SMTP (MIT-0 client). Sender/domain/TLS and actual delivery need operational verification. No new email SDK is needed. |
| Sharp, Leaflet, QRCode, fflate, icons | All have actual functionality. Licences include Apache-2.0, BSD-2-Clause, MIT and ISC; Sharp's native libvips packages include LGPL notices. Preserve native optional packages and notices; do not replace byte validation with a weaker extension check. [Sharp installation guidance](https://sharp.pixelplumbing.com/install/). |
| Razorpay, Meta WhatsApp, Google login, WebAuthn, AI, ABDM, video/imaging | These implement distinct product/protocol requirements, not redundant billing or messaging libraries. External account, data-processing, fees/consent, licensing and deployment terms are separate from SDK licences. No live distributor/API, CDCI approval, automated supplier WhatsApp or production clinical-AI privacy approval is created by an npm package. |
| Sentry / ops webhooks | Optional telemetry. Retain redaction and provider switching boundary; self-hosting a telemetry stack has nonzero operating cost. No new monitoring infrastructure justified. |
| Static landing site | No npm runtime. Google Fonts is an external request; self-hosting licensed font assets is an optional privacy/offline improvement, not a reason to add a frontend framework. No unrelated visual redesign. |

Advisory evidence: [Undici's upstream security advisories](https://github.com/nodejs/undici/security/advisories) and the npm audit snapshots retained beside each inventory. Overrides pin patched versions; review them when compatible parent packages absorb these fixes rather than keeping permanent unexplained pins.

## Technical debt deliberately retained

- Two backend runtime-cycle candidates remain: `AuditLog` / `AuditTrailService`, and session helpers / session resolver / WebSocket revocation. They touch atomic audit and live authentication behavior. Startup/regression checks pass; isolate them in dedicated changes rather than introducing an untested dependency-injection layer.
- Exact duplicate calculation files are deliberate frozen offline protocol versions used to verify already-issued invoices. Do not replace them with an alias to mutable current calculations. Generated frontend offline code is also build output, not abandoned competing logic.
- Frontend queue page (~3,908 lines), billing page (~2,017), appointments (~1,921), browse detail (~1,888), plus backend queue (~2,448), onboarding (~1,985), public (~1,804) and auth (~1,638) controllers are maintainability hotspots. Size is a review signal, not proof of bad behavior. Extract by workflow with direct tests as those areas change.
- Framework routes, service-worker registration, offline entry bundles, type-only imports, CLI commands and peer packages explain static no-inbound/no-import candidates. No broad file/dependency deletion was justified.

## Verification and limitations

- Backend: **93 distinct focused Vitest cases passed** across tenant repository, real TOTP/root MFA, onboarding, clinical notes, pharmacy onboarding, CRM inbound/delivery/prescription communication, tenant route matrix, payment-provider boundary, database configuration, refund state and disruption flow. One early clinical-suite attempt timed out starting disposable MongoDB; that suite passed on rerun. No business database is used by these tests.
- Backend types and all five executable bundles passed; isolated production-config/startup/readiness/duplicate-port/shutdown checks passed. A fixture TypeScript error discovered during verification was corrected and the type gate rerun.
- Frontend: **35 focused Vitest cases passed** across authentication enrollment/entry, API recovery, PWA and realtime architecture. Application and Cloudflare types, changed-file ESLint, 5 glob consumer checks, native Next production build and Cloudflare production build passed. Isolated Next output is under `.next/architecture-verification`; its automatically inserted TypeScript includes were removed after the build.
- **22 local Cloudflare transport/artifact checks passed** against a synthetic upstream, including credentials, CSRF forwarding, nonce isolation, redirects, all socket paths, revocation and tenant rejection. This is not real backend-session/provider verification. The separate missing-doctor HTTP-status check **failed (200 vs 404)** and remains a release blocker. The harness assertion was preserved; it was excluded only for the separately reported transport run.
- Both whole-lockfile advisory scans are zero after patches. Installed Fastify plugin dependency still resolves. Literal references to the moved WhatsApp processor were updated; the unused clinical repository instance has no remaining references. Both repository diff checks passed.
- `npm ls --all` reports two local optional native/WASM fallback extras (`@emnapi/runtime`, `@img/sharp-wasm32`) in each checkout. They were not declared unused or deleted by hand: native image tooling can discover platform fallbacks dynamically. Clean release `npm ci` and native/image acceptance remain required; lockfile advisory results do not certify the entire locally installed tree.
- Read-only connected database metadata check passed (127 models / 579 indexes / no differences). No live query-plan/load benchmark, container audit, physical printer acceptance, provider-money/message operation, restore drill, deployment or full release suite was performed. Full CI/release gates remain mandatory.
